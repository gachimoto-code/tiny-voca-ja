# 本編のやり方: Qwen3-TTS を教師に、RunPod の Pod で学習する

状態: 実施中（2026-11-17 開始）。計画の正本は [PLAN.md](../PLAN.md)、当日の実行手順の正本は [runpod/RUNBOOK.md](../runpod/RUNBOOK.md)。この文書は「全体のやり方」を1つにまとめた解説で、コマンドの細部はランブック側を見る。

## 全体の流れ

1. テキストコーパスを用意する（ローカル作業、費用なし）
2. RunPod に RTX 4090 の Pod を立て、作業データをネットワークボリュームに置く
3. eSpeak 日本語とアライナーの整合を確認する（Phase 0.5 スパイク）
4. Qwen3-TTS で声を2つ設計し、コーパス全⽂を読ませて教師音声を作る（Phase 1〜2）
5. 読み間違いを選別し、特徴量抽出とアノテーションを行う（Phase 3）
6. tiny-voca 本体を学習する（Phase 4、104k steps）
7. 評価し、ONNX を書き出し、成果物を回収して Pod を削除する（Phase 5）

## なぜ Qwen3-TTS なのか

- 原作者の英語版レシピがそのまま使える教師。生成スクリプト（`scripts/generate_audio.py`）もリポジトリに同梱されている
- 公式に対応10言語の1つとして日本語が明記され、使う2モデル（VoiceDesign、Base）とも対応表に日本語がある。日本語で学習されたネイティブ品質の教師が得られる
- 公式ベンチマークの日本語の内容誤り率は約3.8%（12Hz 1.7B Base、多言語テストセット）。中国語・英語の約0.9%より弱いので、生成クリップは全量を Whisper で書き起こして原文と照合し、CER（文字誤り率）15%超を捨てる選別とセットで使う
- コード・重みとも Apache-2.0 で、レシピ全体を公開できる

## Pod の使い方（詳細）

### アカウントと権限

- RunPod アカウントを作り、予算分（上限 $30）をプリペイドで入金する。自動チャージはオフにしておく（残高が上限として効くように）
- API キーは Credentials → API Keys で作成し、GraphQL API を Read/Write にする。Pod の作成・停止・削除・残高確認はすべてこの GraphQL API 経由。Serverless endpoints の権限は使わないので付けない
- キーは一度だけ表示される。エージェント（Muse）から使う場合は安全な保管庫経由で接続し、実物のキーをチャットやファイルに書かない

### GPU と料金の選び方

- GPU は **RTX 4090（24GB）×1**。原作者が 4090 で学習した実績（104k steps 約7.7時間）があり、レシピの既定値がそのまま使える。VRAM は生成（1.7B 推論 約5〜6GB）、アノテーション（約2〜3GB）、学習（数GB）のどれも 24GB に収まる
- 実価格（2026-11-17 のライブ価格）: Community $0.34/時、Secure $0.89/時。RTX 3090 は $0.22/時だが 3〜5割遅く総額はほぼ同じ、A100/H100 は過剰
- 全工程は 21〜31 時間の見込み

### ストレージの設計（重要）

RunPod のディスクは3種類あり、消え方が違う:

- コンテナディスク: Pod を止めた時点で消える。一時ファイル専用
- Pod のボリュームディスク（`/workspace`）: 停止では残るが、Pod を Terminate（削除）すると消える。止めている間もストレージ課金が続く
- ネットワークボリューム: Pod と独立に存在し、Terminate しても残る。ただし **Secure Cloud の Pod にしか付けられない**

このプロジェクトでは、生成音声（約14時間分）と学習チェックポイントを守るため、**Secure Cloud の Pod ＋ ネットワークボリューム 80GB** を本線にする。Secure は時間単価が上がる代わりに、途中で Pod を作り直してもデータが残る。80GB の内訳はランブック §1（モデル約11GB、特徴量約8GB、チェックポイント約4GB、再生成の余裕込み）。

Community（$0.34/時）で進める場合はネットワークボリュームが使えないので、ボリュームディスクに置いて「Terminate の前に必ず成果物をローカルへ回収する」運用になる。安い代わりにホスト障害で失うリスクがある。

### Pod の作成と操作

- 作成前に GPU の在庫をデータセンター単位で確認する（在庫のないデータセンターには作れない。ネットワークボリュームを作る場合は、先にデータセンターを決めてボリュームを作り、同じ場所に Pod を作る）
- イメージは RunPod 公式の PyTorch テンプレート（CUDA 12.x 系、正確なタグは作成時点のカタログで決める）。イメージの CUDA に合わせてホスト側の最低 CUDA バージョンを指定する
- 公開ポートや SSH は開けない。操作はすべて API（exec）経由で行い、長時間処理は Pod 内で `nohup` + ログファイルで回す
- 止め方の違いを混同しない: **Stop は計算課金が止まるだけ**でディスク課金は続く。**Terminate で初めて全部止まる**。セッションの終わりは必ず Terminate まで行う

### コーパスの運び方

- このリポジトリ（tiny-voca-ja）は private なので、Pod から `git clone` はできない
- コーパス3ファイル（train/validation/test.jsonl、計 約2.9MB）は、エージェントの exec 経由で base64 にしてチャンク転送し、Pod 側で sha256 がローカルと一致することを確認する
- 上流リポジトリ（n4ze3m/tiny-voca）は public なので Pod 上で直接 clone する。モデル類（Qwen3-TTS 2モデル、アライナー、Whisper）も Hugging Face から Pod 上で直接ダウンロードする（いずれも公開モデルでトークン不要）

## Phase 別の要点

### Phase 0.5 スパイク（約30分）

- コーパス500文を `espeak-ng -v ja` で音素化し、出現音素を (a) tiny-voca の76記号＋FALLBACK、(b) アライナー（wav2vec2-lv-60-espeak-cv-ft）のラベル集合と突き合わせる
- 事前確認では、日本語音素 ɯ / ɸ / tɕ / dʑ / ɕ / ʑ / ɴ と長母音はアライナーのラベルに全て存在した。残るは espeak-ng の実出力の確認だけ
- 通れば案A（`text.py` の espeak の声を `en-us` から `ja` に変更し、日本語固有音素を SYMBOLS 末尾へ追加）。ダメなら案B（試作v0のかな変換器をアノテーション側に使う）

### Phase 1 声の設計（約30分）

- VoiceDesign モデルに文章で指示して声を2つ作る。女性は英語版 F2 が想定より若く聞こえた反省から「落ち着いた大人の声」と明示する。男性は落ち着いた低めの声
- 各声で参照文（30〜60文字）を読み上げ、`voices/F2.wav` / `voices/M2.wav` と、読み上げ文を記録した `voices.json` を作る。これが生成全体の声の基準になる

### Phase 2 生成と選別（約10〜16時間、無人運転）

- 上流の `scripts/generate_audio.py` を日本語化して使う。改修は4点: 言語指定を `"Japanese"` に、選別用 Whisper を英語専用（small.en）から多言語版（small）に、棄却基準を WER からかな正規化した CER 15% に、話速検査の前提をモーラ数ベースに
- 生成は `state.sqlite` で再開可能。予算デッドライン（`--deadline-file`）を設定して無人で回し、進捗は `progress.json` で確認する
- review（棄却）率が 30% を超えて続く場合は止める。読みか選別の前提が崩れているサイン

### Phase 3 前処理とアノテーション（約1〜2時間）

- `prepare` で波形・メル・ピッチの特徴量を抽出し、`annotate` でアライナーによる音素アライメントと自動 QC を行う。split ごとに分けて実行する（prepare は split の一致を要求する）
- まず `--limit 50` でスモークし、棄却率が英語版並み（0.5%程度）かを確認してから本番。桁違いに高い場合は Phase 0.5 の判断に戻る

### Phase 4 学習（約8〜10時間、無人運転）

- `tiny_voca.train` を 104,000 steps、GAN 開始 8,000 steps の英語版レシピで回す
- train.py には1回の起動あたりの時間上限（`--max-seconds`、既定3600秒）があるので、上限を大きくするか `--resume` でつなぐ。チェックポイントは `last.pt`（再開用）と `inference.pt`（推論用）が自動で出る
- loss の発散・NaN が続いたら止める

### Phase 5 評価と仕上げ（約30分＋ローカル確認）

- `evaluate` で test の CER と未見文の聞き取りを測る。注意点として、evaluate の未見文リスト（NOVEL_SENTENCES）は英語文がハードコードされているので、日本語の文に差し替えてから測る
- `export` で ONNX を書き出す
- Pod を消す前に、成果物を全部ローカルへ回収する: `inference.pt`、ONNX、評価結果、データセットの manifest/review、annotations のサマリ、`voices/` 一式、ログ
- 回収を確認してから Pod を Terminate し、累積コストを記録する

## コスト管理

- 予算上限は $30。確認タイミングは環境構築後、生成スモーク後、生成完了時、学習の折り返し、評価前
- 停止条件: 累積 $25 到達（$5 は予備）、生成の review 率 30% 超の継続、学習の loss 発散、想定外の有料オプションやライセンス同意画面
- Secure（$0.89/時）で全工程を回すと上限に近づくため、フェーズごとにコストを見て、必要なら生成・学習の前に藤本さんへ確認する
